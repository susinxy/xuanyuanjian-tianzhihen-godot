## 1. 事实底座（本会话实证过的，非文档背诵）

### 1.1 已定罪并修复：自回访不倒带（H1）

- **症状**：向右攻击偶发卡死在 attack1 末帧，游戏本体正常（调试坞 Tab 可用）。
- **根因链**：末帧信标（0.333333）触发的那一拍，脑（游戏 FSM）同步切回 Idle 并
  `travel("idle")` 登记；**下一次动画树推进之前**（一个帧间隔，~16ms），玩家的
  下一次攻击点击合法到达（状态已是 Idle、连段窗已被 `exit()` 重开）→
  `travel("attack1")` 覆盖未消费的目的地 → **目标==当前** 且节点从未失活 →
  引擎不重入、位置不归零 → 推进区间 `(end, end]` 空区间 → 方法轨道永不触发 →
  攻击态唯一出口永闭 → 冻结。
- **修复**：皮肤层 `transition_to()` 唯一登记处，目标==当前时改走
  `_playback.start(anim_state)`（即时重入+倒带）。角色线
  `QuiverCharacterSkinAnimTree` 与法术线 `SpellSkinAnimTree` 同案同修。
  注释见源码，行为语义见 PLUGIN_ARCHITECTURE 皮肤章节。
- **武器淘汰史**（全部复现台实测裁决，勿再走回头路）：
  - `parameters/.../seek` 根/子节点写入：**静默无效**
  - `current_position` 直写：**写后读回不变**（只读参数）
  - 空等自愈：**不存在**（双转换后不干预=永久死）
  - `start("idle")+travel("attack1")` 与 `start(attack1)` 单发：**均有效**，选后者（零魔法状态名）
- **取证方法论沉淀**（已入 AGENTS 陷阱清单）：
  - `AnimationTree.advance()` 只计算输出，**方法信标要真实 process 提交阶段才响**（手动推帧测信标=假现场）
  - headless 测动画需 `process_callback` 置物理回调（值=0；枚举成员名各版漂移，按值行事）
  - GDScript 覆写 `_gui_input` 会静默顶掉 ScrollContainer 原生实现且无法 `super()`——同类"取证改变案情"陷阱

### 1.2 关键引擎语义（travel/信标/混合器）

- `travel()` 是**单槽目的地登记**，不是队列：后一次 travel 整槽覆盖前一次，并
  从"当前所在位置"重算路线；目的地==当前 → 空路线 → 无事发生。
- 登记被消费的时机是**下一次动画树推进**（脑同步、身体异步，中间隔着整整一帧）。
- 方法轨道触发 = 播放位置在 `(from, to]` 区间内**跨过**键时刻；空区间跨不过任何键。
- 同一次推进跨过多枚方法键时，各调用在**提交相位按时间序排队补发**——这是
  故事二（§2.2）成立的机制基座（工作模型，与守卫注释及代码路径一致；**未**被
  复现台现行捕获过实弹，属推理，见 §4 诚实声明）。

### 1.3 匿名广播与守卫现状

  全皮肤所有动画的尾铃走同一根匿名线。

  `SpellSkinAnimTree.end_of_spell_animation()` 同构存在。
- 监听者清单（若将来做信号改型，改动面=以下 6+2 处，全部运行时
  `connect_between`，**.tscn 内零编辑器接线**，实查确认）：

## 2. 三个已识别、未修复的架构问题（机制推演）

### 2.1 匿名广播 → 依赖旁证猜身份（守卫的存在理由与软肋）

**故事二（守卫正确工作的场景，推理级）**：单拍 delta ≥ 0.125s 的大卡顿同时跨过
0.2083 与 0.3333 两枚键 → 提交相位按时间序补发：第1声处理中脑已同步切 attack2
（监听换岗、travel(attack2) 挂起）→ 第2声（attack1 的尾铃）撞进 attack2 的
**合法在岗**监听器 → 若放行，attack2 出生 0 帧被处决。此时
connect/disconnect 生命周期**无能为力**（问题不在谁在听，在铃声没身份）；
守卫以"path 非空⇒残尾铃"旁证拦下，**在攻击边全瞬切的前提下，该推断经穷举
未发现反例**（新状态的尾铃物理上不可能同拍到达；自回访不产生 path，实证
path=[]）。

守卫的两条软肋：
- **误吞通道**：合法尾铃 + 恰好挂起的 path（见 §2.2 两条边配置，均可制造）；
- **正确性外置**：它的可靠性建立在"代码之外没人改过边配置"这个巧合上。

### 2.2 AT_END 边 × BlendSpace 状态节点 = 双料死锁

若有人给攻击状态任一边设 `advance_mode=2`（AT_END_OF_CURRENT，UI 名
"Smooth Transition/等待当前动画"一族，直觉上恰是"让上一段放完再进下一段"的
**字面最像正解的错误答案**）：attack1 状态节点是 AnimationNodeBlendSpace2D，
**混合容器从不报告 is_finished** → path 永久挂起 → ①守卫从此吞掉一切尾铃
→ 冻结（且比 H1 更恶毒：每次都冻）②即使拆守卫，身体也卡在边上永不切入新动画
→ 同样冻。**该配置独立致死，守卫只是让它死因难查。**

### 2.3 xfade_time > 0 = 守卫盲区 + 判定窗污染

- `arrival`（path 清空）与淡出（权重混合）是两回事：淡出**期间** path 已空，
  outgoing 动画的尾铃照样跨过 → 守卫放行 → attack2 误杀（故事二回归，且这次
  连旁证都失效了）。
- 攻击盒 value 轨道（`CollisionShape2D:disabled`）在淡出期间被新旧两个动画
  **双写**，布尔混合无语义 → 判定窗口开合时刻不可预测。
- 进边（idle→attack1）同样中招：起手几帧的攻击盒可能与 idle 残留值打架。
- 附加：不同名动画混权区域有引擎字符串损坏前科（八向混合事故），非主论据，
  记档备查。

### 2.4 信标独木桥出口无运行期兜底

attack/impulse/landing/spell 引导态的出口**只有**信标（air_attack 有
`_end_condition` 枚举先例）。信标丢失路径当前已被 18 号回归套封死，但结构上
无第二保险：未来任何新丢失路径 = 永久冻结，无自恢复、无运行期记录。

## 3. 三个候选方案（完整设计留档，全部**未做**）

### 方案一：信标身份名牌（正统解，收益最大成本也最大）

三层链路改造：
1. **资产层**：一次性幂等脚本 `tools/beacon_identity/bake.gd` 给 114 个 tres 的
   `end_of_*` 方法键补 `args=[动画资源名]`；文本手术纪律（锚点验尸+计数断言+
   幂等二次零改动）；chen 非 git → 先出回滚 tar。
2. **皮肤层**：`signal skin_animation_finished(anim_name: String)`；emit 转发
   参数；**守卫退役**（身份键严格更强：既防误杀又根除误吞）。法术线同构。
3. **状态层**：6 个监听者签名加参 + 对号过滤
   `anim_name.is_empty() or name == _skin_state or name.begins_with(_skin_state + "_")`。
   - **空名放行**=未烘焙遗留/第三方皮肤的兼容垫（宁可退回旧风险，不可让缺牌
     变成新冻结源）。
   - 前缀族规则不新增约定——`状态_方向` 命名是全库资产管线的既有强制。
   - 体检器升级：尾铃存在但 args 与资源名不一致 → 红（机械校验，不靠自觉）。
- **不走捷径的理由**：`parameters/current` 反查是观察者视角，交接/淡出瞬间会
  撒谎；名牌必须是出生视角。
- **验证设计**：H4 场景先"只删守卫不烙牌"演红（定罪守卫存在理由），再身份键
  转绿；`tree_connectivity` 套天然兜 arity 漏改。
- **搁置理由（用户决策，2026-09-17）**：信标本来就 100% 手工维护（管线不写
  方法轨道，实查确认），名牌使同一手工步骤多一格 args——但相比守卫
  "零配置"的性质，它仍是"每资产多一份可错数据"；114 文件烘焙+6 处改型+守卫
  退役的工程量与风险面，对当前收益比不划算。
- **重估触发条件**：①下次资产全量 re-bake（烘焙边际成本趋零时顺路上牌）；
  ②守卫旁证被任何新场景打破（§2.1 穷举被证伪）。

### 方案二：转换边配置锁（守卫生命线的工具化，最小成本方案）

- 动画树体检新增规则：**名单状态的任一边（进+出）`advance_mode==0` 且
  `xfade_time==0`**，违者面板红字点名。
  名单：attack1/2/3、spell_start/spelling、hurt_high/mid、landing、impulse、die。
  出边防 §2.2 冻结与 §2.1 误吞；进边防 §2.3 攻击盒双写。击倒子机 at-end 合法

- 可选实证 H4″：测试树动态设 at_end/xfade 边 → 连段必冻/必误杀的红案提取。
- **搁置理由（用户决策）**：现状配置健康且无自动化路径会改坏它（唯一入口是
  编辑器手工操作），风险以"认知+本文档"承接，暂不上工具锁。

## 4.5 修复本体的后续演进（2026-09-17 追加，覆盖 §1.1 中"自回访=start"的初版判据）

初版"目标==当前一律 start()"引发回归：mid_air 每帧幂等登记 rising/falling
被逐帧倒带→腾空动画钉死首帧（b4ab831 一修改用"动画已播完才倒带"的位置判据，
又被发现会在长滞空时于尾帧重启重播——**而"停在尾帧"恰是悬停姿势的设计意图**，
rising/falling 不做循环即此用意，勿再"顺手改循环"）。终版判据（38fedde）：
皮肤跟踪 `_brain_destination`（脑最近指挥的目的地），自回访**仅脑改过主意才
start() 倒带，同目的地幂等登记恒 no-op**——判据从身体时钟换成脑的意图，
不再读任何树参数。复现台扩为五场景，H6 双断言锁两面。教训：**幂等登记型
调用方（每帧重申同一目的地）与一次性指令型调用方共存于一个 API 时，
"是否重播"必须由调用意图裁决，身体状态只是被同步的对象。**

## §6 复测定案（2026-09-26，守卫拆除案卷）

本案卷 §2.1"故事二"（守卫唯一辩护场景）与 §2.3"xfade 盲区"在 4.7.1 探针实测下双双证伪，
守卫已从 `QuiverCharacterSkinAnimTree` 拆除（基类直发），全矩阵 25 跑 RED=0。案卷：

- 单铃跨拍（XFADE 0.3s/即时 双形态、打断在途/短动画四场景）：**六次合法发射全部
  `travel_path=[]`**；被离开状态的旧动画时钟冻结，尾铃物理上不跨——守卫零触发面。
- 双铃同拍（本案卷故事二的原样复刻：同拍两枚方法键，铃1 handler 内同步
  `travel("B")`）：铃2 到达时 **`cur=A` 且 `path=[]`**——travel 的登记要到下一拍
  才在 path 上显形，守卫在其假想场景里同样吞不到任何东西。
- §2.3 的"淡出期 outgoing 尾铃照样跨过"预言落空：淡出中方法轨道不响应
  （=上条实测），该盲区不存在；同时"守卫放行→误杀"链亦不存在。
- 净结论：守卫在全部可测形态中要么透传（无害），要么（若真跨拍挂起 path）反而
  具备吞真信标的负风险。拆除为行为等价变换（六发全同）。

探针与 FIRETABLE 原始数据：`/tmp/opencode/b46_guardprobe/`（probe1-4；探针场景为
一次性形制：双态 SM + 0.4s 非循环动画 + 末帧/同拍双方法键）。
**§4 诚实声明中"未被复现台捕获过实弹"的状态就此更新：已捕获，实弹哑火。**
