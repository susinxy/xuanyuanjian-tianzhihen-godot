## 头部纪律（必读，全部是本仓库判例）

1. **SaveSystem autoload 入册核验（编辑器关口令流程）**：T0 经用户口令"关了"
   后在 `project.godot [autoload]` 的 GameSave 行**之后**加了
   `SaveSystem="*res://scripts/save/save_system.gd"`（顺序即启动序——影子监听
   者必须后于账本入树，前置探针实锤按注册序）。**重开编辑器后**去
   Project Settings → Autoload 确认 SaveSystem 在位且在 GameSave 之下；
   缺席=`project.godot` 被编辑器旧内存回写吞过（本月三案判例），报回勿硬跑。
2. **首开"内容不变重存"补 uid 指纹——勿慌**：本批新脚本/夹具未带 inline uid，
   Windows 编辑器首开会自动补写并重存（伴随症状=同会话加载过的资源批量刷
   mtime）。git status 复核只多 uid 行内容未变=正常；出现语义变化才报案。
3. **记事本禁令（影子落盘的 Windows 侧雷）**：Windows 上"改名覆盖已存在文件"
   走引擎先删后移、**非原子**——验收期间**勿用记事本常开 `save_auto.json`**
   （占句柄会让帧尾改名落盘 push_error 丢一次影子；丢档可接受，但观感噪音
   会污染本案卷）。要开就"打开→看完→关掉"。
4. **继续钮 enabled 只在标题 `_ready` 评估**（T2 移交眼验项）：同一进程里先开
   标题再游玩产生存档后**返回**标题壳，钮不会实时变亮（无中途刷新）——正式
   流程"游玩→ESC 回标题"会重建标题壳，正常；手测别拿常驻标题页说事。
