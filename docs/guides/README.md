# docs/guides/ —— 用户操作手册专区

本目录**只放直接交给内容贡献者的实操说明书**（GUIDE_<域>.md 一族）：
流程步骤 + 配方卡 + 常见病处方，读者不需要打开代码编辑器。

| 文档 | 管什么 |
|---|---|
| `术语表.md` | **先收藏**：搭建词汇、校验器报错编号速查、工程黑话翻译、键位速查 |
| `GUIDE_关卡搭建.md` | 壳+段搭章节、互动件摆放、验收步骤、零件库 |
| `GUIDE_格挡.md` | 格挡/弹反时序平衡、格挡动画换图与帧轨纪律 |
| `GUIDE_光照.md` | 昼夜数据、阴影区域、软边（原 LIGHTING_SETUP_GUIDE，2026-09-28 收编改名） |

## 写作守则（2026-10 文档整改批定档，写给工程侧，也约束未来的每本新手册）

1. **人话优先**：读者是"不开代码编辑器的内容贡献者"。自造词、内部黑话、
   工程批次编号一律禁止出现在正文——需要引用时挂到 `术语表.md`，正文用
   大白话（"踩过的坑"而不是"判例"，"必须改回来"而不是"回炉"）。
2. **每本手册开头两行**：这本管什么 + "不懂的词去哪查"（指向术语表）。
3. **手册与代码零漂移**：手册里每个路径/字段/键位/文件都必须实查现状后再写；
   每次工程批次改了玩家能碰到的东西（改键、改默认值、挪文件、改壳内容），
   交付清单必须含"同步检查受影响手册"。写完自查一遍：手册的说法编辑器里
   真能看到吗？
4. **不写工程纪律**：提交规矩、测试矩阵、案卷论证属于工程文档，
   手册只留"玩家/作者视角怎么办"。
5. **法律条款指针引用**：红线原文在法典（STAGE_ASSEMBLY 等），手册只讲
   "怎么点"+编号；报错编号的权威定义以 `tools/stage_validator/validator.gd`
   实际行为为准，术语表是它的翻译不是替代。
6. **历史案卷不混入**：法典、源码分析、设计案卷、PLAN/spike/specs 留在
   `docs/` 原位；改名/迁居本目录文件时，活文档互链同批改（历史案卷不回改）。

## 维护规则（与 M3 可生产性铁律配套，沿用）

每批交付新内容能力，工程侧必须在本目录登记/更新对应 GUIDE（铁律三件之一：
编辑器入口 + 说明书 + 报错即教学）。
