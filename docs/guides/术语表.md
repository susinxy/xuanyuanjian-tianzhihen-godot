## 一、搭建词汇

| 词 | 人话解释 |
|---|---|
| **壳**（章节壳） | 一章一个的场景文件（`chapter_1.tscn`），负责"整章共用的一切"：主角、跟随相机、界面 HUD、暂停/死亡菜单、终点面板、昼夜光照。模板在 `scenes/chapter/chapter_shell.tscn`，用"场景另存为"变成你的章。**壳里不预置主角**——你把想用的角色 .tscn 拖进壳根的 `playable_override` 属性即可，想换主角就换个文件拖进去 |
| **段** | 一章里"一幕戏"的场景文件（`seg01.tscn`），只放这段场地长什么样：可行走盒、房间/遭遇带、敌人从哪刷、宝箱摆哪。**段里不放玩家/相机/HUD**（那些归壳管，一份就够） |
| **段模板** | `scenes/chapter/segment_template.tscn` v2，一个满配的战斗段样板（盒/房/遭遇带/刷怪点/检测器/入口全预置）。建段=复制它改名，红线清单写在根节点 Inspector 最底部的 `_assembly_notes` 里 |
| **盒（PlayfieldBox）** | 段的第一件家具：一个虚线矩形框=**人能走的范围**。四面的隐形实体墙和地板色块由它在运行时自动生成（所以文件里翻不到"墙"这个节点，想改边界就拖框）。一段只准一个盒，框内=可移动区。旧形段里手摆的 `GroundBody/WallL/WallR` 仍合法（存量段专用，新段勿抄） |
| **遭遇带** | 不锁镜头的刷怪带：一个 Node2D 容器里放检测器+刷怪点，**不需要房**（玩家跨线就刷怪，打完段照样判清）。段模板 v2 里的 `Encounter1` 就是它的抄本 |
| **房（战斗房）** | 段里一个白色虚线框（节点 `Room1`）。玩家走进框内的触发带就会"锁镜头+刷怪"，打完才能继续前进。**房是可选家具**（特写/锁战才摆），开战与战斗本身不依赖房 |
| **检测器 / 触发带** | 房里的一条绿色竖直触发区，玩家碰到就开始战斗。它同时负责判定"这个房的怪是不是全打完了" |
| **生成器（spawner）/ 波次** | 刷怪点。Inspector 的 `spawn_waves` 数组：外层一项=一波，内层一项=这波里的一个怪（下拉选哪个角色 .tscn） |
| **判清 / 段清** | "这个段的所有怪全被打完"的状态。段判清后相机自动向东扩（能继续往右走），有下一段就自动切下一段 |
| **章终点 / 终点面板** | 一章最后一段判清后自动弹出的面板（返回标题 / 重走一遍）。所以**跨章出口（StageExit）要摆在"永远不会打完"的过场段**，不然是够不着的 |
| **过场段** | 不打怪的一段：删掉房和遭遇带（**盒留着**）、根上勾 `auto_complete`（一进就算打完直接推进）。以后放对话/剧情就放这类段 |
| **被控角色** | 当下由玩家键盘操控的那个角色（代码里旧名 `playable`）。壳开场时=你申报的主角；段可以换人（见关卡搭建配方卡），换的只是"谁归你操作"，阵营出身不变 |
| **行为互换** | 换人操控的默认处理：新被控者接管时，旧被控者接过新被控者原来的"档位"（AI 自动打/站桩不动），像交班 |
| **回正** | 某段没有特殊申报时，进入该段自动换回壳指定的初始被控角色（严格申报制：每段的开局只由该段自己决定，不存在"上一段换的人忘了换回"） |
| **慢放集** | "死了值得给一段慢镜头的人"名单（段/壳可各自申报）。不申报时默认=结算集（谁之死算败北谁有演出）。它只管观感，不管输赢 |
| **结算集**（不能死名单） | 谁之死=游戏败北（慢放→结算画面/重跑的触发集合）={终局锚点}∪{被控者} |
| **终局锚点**（护送对象） | "剧情上不能死的人"：段或壳的 `defeat_anchor_path` 申报谁，谁被怪打死=游戏和你一起输（慢放+回检查点，待遇与你自己阵亡相同）。都没申报时只有被控角色之死算败北；你自己操控的角色**永远**算败北条件（护送时你死了也一样输） |
| **检查点** | 你走到哪章哪段被自动记录，死亡后从那重来（已开的宝箱等记录不会丢） |
| **账本** | 游戏的存档记录（谁开了哪个宝箱、学了哪个法术、到过哪）。互动件都自动记账，不用你管 |
| **互动件（触发件+反应件）** | 宝箱/秘籍/门/QTE 的四件套玩法：摆一个 `interact_trigger.tscn`（按 E 的触发框），在它下面挂一个反应脚本（`InteractChest` 等）。每类件要填的唯一编号（`chest_id` 等）**同一章内不许重名**，重名校验器会点名 |
| **昼夜三件套** | 壳里预置好的 `Ambient/` 三个节点（画面色调/光源/昼夜控制器）。不挂时间数据=一直白天；想有昼夜就挂一份数据文件，细节见 `GUIDE_光照.md` |
| **软边阴影** | 角色脚下阴影的柔化效果，**默认已开启**。按 L 键可在"硬边/软边"间切换对比，纯调试用 |
| **校验器** | 一条命令的"装配体检"工具（见关卡搭建手册第 4 步）。查出问题时给编号+处方，编号在下方速查表 |
| **回归矩阵 / 契约** | 工程侧的自动化测试总闸（`tools/matrix_runner/run_matrix.sh`），每次工程改动后由工程侧跑。内容搭建一般用不到它，听到这俩词知道是"我们的体检系统"即可 |

## 二、校验器报错编号速查（与 validator 实况一致）

报错原文每条都自带"怎么改"的提示，这里是速查版：

| 编号 | 意思 | 通常怎么修 |
|---|---|---|
| R1 | 章文件的根节点不是合法形态（章文件必须是通过"场景另存为/实例化"从壳模板来的），或文件为空/被截断 | 确认章文件是从 `chapter_shell.tscn` 另存或实例化的；被外部工具改坏就重存 |
| R2 | 没填身份编号：壳没填 `chapter_id`、段没填 `segment_id`，或填了空串 | 在根节点 Inspector 填上（壳的章编号**全游戏唯一**，段编号章内唯一） |
| R3 | **已降黄**：房里没有检测器触发它（纯特写房合法，只是"没人来就永不解锁"） | 打印成 `NOTICE` 提醒、不算违例；确属有意就留着，想要自动解锁请找工程侧立项 |
| R4 | 接线问题两种：①**哑检测器**=检测器既没指房也没列刷怪点（触发了无人应答）；②**孤儿刷怪点**=某个 spawner 没被任何检测器引用（波永不刷、段永不判清） | ①给检测器填 `paths_enemy_spawners`（无房的遭遇带可以不填 `path_fight_room`）；②把该 spawner 列进对应检测器的数组，或删掉它 |
| R5 | 刷怪点的"怪生到哪个容器"（`path_spawn_parent`）不是合法值 | 保持段模板默认值 `../../../../Players`，别手改 |
| R6 | 刷怪波次里某张卡的 `enemy_scene` 没指到真实存在的角色文件 | 下拉重选一个存在的 .tscn；删怪卡时整项删干净 |
| R7 | 手摆的场地/墙物理配方被改（`collision_layer` 必须含全部高度层=16760832，且不能带旧屏幕限位 12）。**旧形段专用**：盒段的墙带由 PlayfieldBox 运行时派生，文件里没有墙=查不到也不会红 | 改回 `collision_layer=16760832`、`collision_mask=0` |
| R9 | 同一个刷怪点被两个（或更多）**检测器**同时引用→争抢波次所有权（判据已去"房"化，无房遭遇带同样入网） | 一个刷怪点只归一个检测器管；要两批怪就拆成两个 spawner |
| R10 | 背景图层的 `layer` 写了 ≥0 的数（会把角色和阴影整个盖住） | Background 的 CanvasLayer `layer` 改成负数（如 -1，debug 背景用 -10） |
| R11 | 互动触发件没有碰撞形状（按 E 永远碰不到的隐形件） | 给它补一个 `CollisionShape2D` 并画出大小 |
| R12 | 反应件的账本编号（`chest_id`/`spell_id`/`manual_id`）没填，或同户在同一章里重名 | 每件填唯一编号；两件要各自记账就起不同的名 |
| R13 | **盒轨**（段里摆了 PlayfieldBox 才查这族；没摆盒的旧形段不查）：①一段摆了两个盒；②盒动了 `anchor_*`/`scale`/`position`（坐标系失配）或没直挂段根，或框没拖开（零面积）；③出生点 `entry_points` 落在盒外。另有**黄字**（不算违例）：某个房的矩形超出盒界 | ①删掉多余盒；②选中盒把 anchor/scale/position 恢复默认（用四边把手拖框，只改 `offset_*`），并把盒挂回段根、把框拖出面积；③出生点挪进盒内；黄字则收房进盒或当作有意的远景装饰 |
| R14 | 壳没有主角来源（override 没拖、Players 也是空的） | 把玩家档角色 .tscn 拖进壳根 `playable_override` |

> 注：R8 已随旧单地点形制退役（不再出现）；`NOTICE`/黄字（R3 黄、R13 房越盒黄）
> 只提醒不计数，报"违例 0"才算体检通过。
> 多件文件同时报错时先修最前面的——很多错误是同一根因的连锁。

## 三、工程文档词汇翻译表

工程侧的文档（法典、案卷、更新记录）爱用这些黑话。你读到它们时按右列理解：

| 工程黑话 | 人话 |
|---|---|
| 判例 / 案卷 | 踩过的坑的记录 / 按时间归档的改动记录 |
| 法源 / 法律来源 | 这条规矩的原始出处文档 |
| 铁律 / 宪章 / 禁令 | 必须遵守的规矩（多数有校验器或自动测试兜底） |
| 回炉 | 违规了，拿回去改 |
| 执法 / 回归锁 | 用自动测试盯着，改坏了会亮红 |
| 合流 / 提交 | 工程侧代码入库动作，与内容搭建无关 |
| 吞改 | 编辑器开着时从外部同步进来的改动被旧内存版覆盖掉（见关卡篇常见病） |
| 哨兵 | "留空=自动"的特殊默认值 |
| 机检 | 用命令自动检查，不靠肉眼 |
| 记账户 / 同户 | 存档里一类记录一个"户头"；同类件才比较重名 |
| S2-B4.8、5a、5b、S5b 这类编号 | 工程开发批次号。读文档只当时间戳用，不影响施工 |

## 四、键位速查（project.godot 实况）

| 键 | 干什么 |
|---|---|
| 方向键 / WASD | 八向移动（斜走是合法的） |
| Shift（按住） | 慢步走（默认速比奔跑慢） |
| 空格 | 跳跃 |
| J | 攻击（三连段） |
| K | 格挡/弹反（点按，不可长按） |
| E | 互动（宝箱/秘籍/门） |
| 1 / 2 / 3 / 4 | 放法术槽 1-4（要先通过秘籍学会；目前现成法术只有火球） |
| ESC | 暂停菜单 |
| R | 快速重开本关（调试用） |
| L | 软边阴影开/关对比（调试用） |
| V | 命中特效开/关（调试用） |
| `=` 或 `+` | 唤出/收起调试面板 |
| 5/6/7/8 | 切昼夜相位（调试面板开着时） |
