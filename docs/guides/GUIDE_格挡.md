# GUIDE_格挡 —— 格挡/弹反的换图与调参说明书

> 谁该看：想给角色换格挡姿势图、或调整弹反/持盾时长的内容贡献者。
> 本手册只需要 Godot 编辑器；不懂的词查同目录 `术语表.md`。
> 想先体验：进游戏**点按 K**——角色架盾起手，随后自动收拳。

---

## 0. 三十秒版：不开代码能改的三件事

| 想改什么 | 改哪里 |
|---|---|
| 格挡姿势的图 | 角色目录 `resources/sprites/block_out/right/`、`resources/sprites/block/right/` **同名覆盖**（§2.2）。左向姿势会自动跟着变，不用单独画（§2.3） |
| 弹反/持盾的时长 | 双击对应 `resources/animations/block_out_right.tres`（或 `block_right.tres`）改 `Length`——**必须同步挪末帧方法键**，见 §2.4 |
| 格挡火花好不好看 | `scripts/effects/presets/spark_parry.tres`（弹反蓝白火花）/ `spark_block.tres`（格挡暗金火花），纯观感参数，随便调（§4） |

## 1. 机制是怎么运作的（玩家视角）

### 1.1 点按，不是长按

按一次 K = 启动一段固定序列：

```
点按 K → 起手架盾（这一小段=弹反窗）
        →〔这段时间弹开了攻击〕起手动作放完后直接收拳——弹成=马上能打回去
        →〔没弹到〕   进入持盾段（这段时间=普通格挡窗）→ 自动收拳
```

- **按住 K 不会连架**：这一套做完，就算手指还按着也不会自动来第二段，必须松手再点。
- **动作进行中再按无效**：不会打断重入。
- 挨打、被击飞、被抓时会立刻干净退出格挡，不留残留状态。

### 1.2 弹反和格挡的待遇区别

| 挨打瞬间你处在 | 叫什么 | 结果 |
|---|---|---|
| 起手段 + 盾面对着装方 | **弹反** | 不掉血不被推；打你的人反而被顶退、愣一小下；放蓝白火花；你立刻收拳可反击 |
| 持盾段 + 同面 | **格挡** | 掉血 = 原伤害 × 0.4（每个角色可调）；这下的击退整个作废；放暗金火花；你的持盾不中断 |
| 时段对但**人在你背后打你** | 没防住 | 按普通挨打：满伤、可能被击退、出受击动作（背后偷拳穿盾是有意设计） |

一句话：**挨打 < 格挡 < 弹反**。弹反是零成本还送反击窗口，所以正确玩法是弹完立刻打回去，而不是再架一次盾。

### 1.3 只认左右两面

- 盾只有左/右两个面（和攻击朝向设置无关，永远是水平判定）。
- 按下瞬间你的面朝哪边，盾就挡哪边；整套动作期间不会转头。
- "敌人算从哪边来的"看接触点在你身体中线左边还是右边。所以**从画面纵深方向（上/下）打来的敌人，按其左右偏移归类**——站对方向就能挡住，这是玩法不是 bug。

### 1.4 出招后也能接格挡

站立/走路/跑步/地面三连招的收招期间按 K 可以直接取消进格挡。**空中攻击之后不能架**（空中无防御，有意设计）。

### 1.5 画面比判定慢 2~4 帧（知情）

弹反窗从**按下那一刻就生效**，但你看到举盾姿势晚几帧才出来（动画要经过待机中转）。看着"慢半拍"是正常现象；真觉得碍眼，反馈给工程侧记入手感单，这不是本手册可调项。

### 1.6 时长就是动画时长

**弹反窗长 = `block_out` 动画长度；持盾窗长 = `block` 动画长度。**
改动画就是改战斗平衡——是特性不是巧合，所以动之前先看 §2.4。

## 2. 换图与改帧

### 2.1 文件地图（每个角色目录内，实查现状）

```
characters/<阵营包>/<名字>/resources/
├── sprites/block_out/right/block_out_right_00.png … _12.png   ← 起手(弹反)段 13 帧真图
├── sprites/block/right/block_right_00.png … _15.png           ← 持盾段 16 帧真图
├── animations/block_out_right.tres / block_out_left.tres      ← 时长与方法键都在这
├── animations/block_right.tres     / block_left.tres
├── spriteframes_<名字>.tres        ← 图片登记表（只有增减文件数才动）
├── anim_library_<名字>.tres        ← 动画登记表（同上）
└── animations/animation_tree_root.tres                        ← 动画树（勿手改）
```

### 2.2 换图 = 同名覆盖

1. 画好新图，**按现有文件名**（`block_right_00.png` 这样带两位编号的）盖进对应目录；
2. 回 Godot 编辑器等底部扫盘/导入完成（外部改过文件后长时间开着的编辑器**建议重启**——曾有编辑器用内存旧版把外部改动盖回去的事故）；
3. F6 跑一下，按 K 目验姿势。

想**加帧/减帧**：文件按编号顺延（`_16`…）没问题，但登记表和动画里的"帧号轨"要跟着改（§2.5）——第一次做建议拉工程侧一起，做完必跑 §2.7 的快速验证。

### 2.3 左向姿势不用画（自动翻面）

左目录**不存在也不需要存在**：`block_left.tres`/`block_out_left.tres` 这两条动画直接**复用右向图 + 自动水平镜像**（动画里自带 flip 轨道）。

所以：**只换 right 目录的图，左右两个方向的格挡姿势一起更新**，不存在"画反了二次镜像"的坑。这一族与 idle/walk 等所有其他动画的左右处理方式相同。

### 2.4 调时长 = 调平衡（改一个数必须同步挪一个键）

用 Godot 编辑器就能改，无需开文本：

1. 双击 `animations/block_out_right.tres`（弹反窗）或 `block_right.tres`（持盾窗）；
2. Inspector 顶部 **Length** 改成目标秒数（现值：弹反 0.1 秒≈6 拍、持盾 0.3 秒≈18 拍；"拍"=物理帧，1 秒 60 拍）；
3. **同一条动画里的 `method` 轨道上，把末尾那个呼叫 `end_of_skin_animation` 的紫色方法键拖到新的结束时刻**。
   ⚠️ 这一步不能省：状态机就是靠这个"收工铃"推进序列的。**改了时长忘挪方法键 = 收工铃永远不响 = 角色架着盾冻在原地**，不崩不报错，很难查。
4. 左右两张 `.tres`（如 `block_right` 和 `block_left`）要改成同样时长；
5. Ctrl+S，F6 实测。

改时长前想一想：这是在改战斗平衡（弹反窗越宽越容易防住），正式定值前最好过一下设计讨论。

### 2.5 播放的真相：动画资源里的三条轨（加/减帧前必读）

动画播成什么样**全由 `.tres` 自己决定**，SpriteFrames 面板里的 fps 字段只是编辑器预览速度，运行时不参与。每条动画资源内部有三类轨道：

| 轨道 | 干什么 |
|---|---|
| 动画名轨（`animation`） | 声明播 SpriteFrames 里登记的哪条动画 |
| **帧号轨**（`frame`） | 按时间把帧号从 0 推到最后一帧——**画面推进的真引擎** |
| 方法轨（`method`） | 时段末尾敲"收工铃"（§2.4 那个键），弹反窗=这一段 |

加/减帧后的同步动作（编辑器内可做）：

1. SpriteFrames 面板把新图登记进动画；
2. 双击对应 `animations/*.tres` 进动画面板：把**帧号轨最后一个键的数值**改成 `帧数-1`（键的时刻保持在末尾）；
3. 若同时改了时长，把**方法轨键**挪到新末尾（§2.4）。

三处对不齐，工程侧的自动检查会报红并给出改法（它只查"这几条关系对不对"，**不规定**每个角色该几帧几秒——那些本来就该各异）。

> 沿革（想深究再读）：2026-09-27 曾按"胶片=帧数÷fps"的错误模型全库调过 18 处
> fps，次日被指正全部撤销；纠错后的自动检查随即抓到 9 处真错位（含 block 左向
> 动画帧轨只铺到 8/16），均已修复。现行模型即本节。

### 2.6 没有格挡动画的老角色会怎样

B4.8 之前出生的角色（或你手动删了槽）：格挡**照样可用**——时序改由备用常数（起手 12 拍/持盾 30 拍）说话，姿势=上一个动作的定格画面。每次进入会打一行提示
`B4.8: 皮肤 <名字> 缺格挡动画槽，走兜底帧数时序`——是提示不是错误。想补动画：从 `templates/character/` 新角色的格挡四件复制过去，或重新用创建面板生角色。

### 2.7 验证（改完之后跑什么）

- 快速单验格挡链：
  ```
  bash tools/matrix_runner/run_matrix.sh --ensure-only
  godot.exe --headless --path . res://tools/block_parry_contract/block_parry_contract.tscn
  ```
  最后一行 `block_parry-contract: PASS` 即绿（这一步是工程侧命令，内容侧改动由工程侧代跑也行）。
- 改的是**模板**（`templates/character/…`）影响以后新建的所有角色；改的是某个角色只影响它自己。chen 和模板是两份独立文件（内容相同但互不传染）。
- ⚠️ 禁止为"对齐"去全量跑 `tools/sync_template_from_chen.py`——chen 已有内容侧漂移，整脚本重跑会顺带改写几十个无关文件。定向复制目标文件即可。

## 3. 常见错误解读

| 症状 | 最可能原因 | 处置 |
|---|---|---|
| 按 K 没反应 | 手指没松开（点按制）/ 在空中 / 正在挨打·击飞·另一段格挡里 | 松手再点；落地再架；被打断是设计 |
| 架盾后角色冻住不收拳（不崩不报错） | **方法键没跟上新时长**（§2.4 生命线） | 把末帧方法键挪到动画结束处；跑 §2.7 验证 |
| 明明"在挡"却满伤 | 方向门：敌人在盾的背面一侧（纵深来袭按左右偏移归类） | 面向来袭侧再按 K（§1.3） |
| 弹反成功后持盾段"消失" | 设计如此：弹成=立即收拳反击，持盾段只属于没弹到的情况 | 弹完马上打回去；想继续防=松手重按 |
| 弹反"该成功却失败" | 挨打瞬间已错过弹反窗（现在只有 0.1 秒≈6 拍；敌方出拳到命中约 5 拍——**看到对方起手再按必输，要预判按**）或方向不对 | 提前按（判定从按下当帧生效）；或按 §2.4+设计流程加长 |
| 空中拳/弹体也能被我弹开 | 设计如此：方向门只看左右位置，不管攻击来自地面还是空中 | 不是缺陷 |
| 换图后游戏里毫无变化 | 文件名/编号没对上；或编辑器扫盘没完成/长会话盖回了旧版 | 核对 §2.1 文件名；重启编辑器 |
| 输出里反复出现"缺格挡动画槽"提示 | 该皮肤没有 block 动画（老角色/删槽） | 按 §2.6 二选一：补四件，或无视 |
| 想长按一直架盾 | 机制不支持 | 节奏打法：约每 0.7 秒点一次，每次一整段 |

## 4. 参数总表（每个数只住一处）

| 参数 | 现值 | 住哪 | 动它等于 |
|---|---|---|---|
| 弹反窗时长 | 0.1 秒 | `animations/block_out_*.tres` 的 `length` | 改平衡（走 §2.4） |
| 持盾窗时长 | 0.3 秒 | `animations/block_*.tres` 的 `length` | 同上 |
| 缺槽备用拍 | 12 / 30 | `_beat_em_up/action_states/quiver_action_block.gd` 常量 | 工程侧专属，内容侧不用碰 |
| 格挡掉血系数 | 0.4 | 各角色 `resources/<名>_attributes.tres` 的 `block_damage_ratio` | 单角色调参，可直接改 |
| 弹反让对手罚站 | 6 拍 | 同上 `parry_stun_frames` | 弹反奖励力度 |
| 弹反火花 | 蓝白·短促 | `scripts/effects/presets/spark_parry.tres` | 纯观感，安全 |
| 格挡火花 | 暗金·闷响 | `scripts/effects/presets/spark_block.tres` | 同上 |
| 哪些动作后能接格挡 | 站立/走/跑/地面三连 | 状态机进入白名单（工程侧） | 加"空中"需要设计拍板，别现场改 |

> 弹反成功的"立即收拳"若实机觉得过强，工程侧留了回退旋钮（弹成后仍进持盾段但
> 砍半）——走设计流程，不要手改代码。
